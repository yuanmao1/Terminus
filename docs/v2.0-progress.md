## 零、执行期作出的破坏性决策（仓库里唯一的记录）

`docs/v2.0文档.md` 是 174 行的目标陈述，**没有破坏性变更清单也没有 B 类决策表**，所以这些决定只能记在这里。

**1. 撤销 CRLF 默认转换（`b1251e3`）。** 0.1.10 刚把 `--stdin` / `--cmd-file` 的 CRLF→LF 设为默认；现在关闭：
字节原样通过，`--normalize-lf` 显式开启，而输入含 CR 且未开规范化时在 stderr 和 JSON 各报告一次。
保住 0.1.10 真正的价值（让操作者**知道**有 `\r`），去掉危险的那半（静默改字节）。

范围是**命令文本，不含 `--stdin-file`**：在那里 `\r` 是数据，改写它会破坏载荷，并让回执的摘要描述一份不是该文件的字节。
`--stdin-file` 也不对 CR 告警——二进制里 `0x0D` 是常态，每份载荷都告警等于训练操作者忽略告警。

`--raw` 不再影响命令文本（它是旧的 opt-out），仍是 `read`/`write` 的真实 flag。

**2. 一处溯源更正，供以后引用时注意。** 我曾把 no-clobber 的 `ln` 处方引作 `docs/v2.0文档.md` §3.3，把 CRLF 撤销引作 §5.1。
**两者都不在那份文档里**——它没有节号结构。那些详细设计在仓库外的计划文件里，这也意味着**任何 subagent 都看不到它**。
仓库内的权威只有两份：`docs/v2.0文档.md`（目标）和这份台账（执行与决策）。

### 这条支线最后暴露的架构级问题（都已闭合）

1. **"一个销毁合同"是过度声明。** 存在两个:**claim-backed**(`commitDestruction`,持 lease,事务内重读自己的 claim)
   和 **quiescence-backed**(`servers.removeLocked`,不持任何东西,要求整台服务器无人持有任何东西)。
   后者更严,且把它折进前者需要为 server 级动作发明一个 lease。两者互不包含,现已各自命名。
2. **级联集合是隐式的。** `servers` 级联 **7** 张表(不是我先前 grep 出的 10——那是**有 `server_id` 列**的表数,
   其中 3 张是 `SET NULL`)。集合现在从**已应用的 schema** 推导并双向held,新增级联表会点名失败。
3. **两份手写"谁持 claim"清单彼此分叉。** `claim_reporting_bodies` 说 7 个,`claim_holding_bodies` 说 2 个,
   `reportFinishedDuringKill` 在前者不在后者——于是它续租、写终态,而两条续租规则都不看它。现已改为**推导**(函数体内有 `stillOurs(` 即持 claim),
   两份手写清单删除,只留计数;并加了反向不变量(动手的函数体必须也在发布清单里,否则 `ClaimHolderDoesNotReport`)。
4. **写终态前的续租无门禁。** 三处 `_ = stillOurs(...)`,删掉任一行测试全绿。规则不是邻接而是"续租之后不得有远端往返",
   且必须区分**裸结算**(`settleObserved(`,只凭 `authority`)与**合同背书**(走 `commitDestruction`,事务内重读)——
   否则 `removeSession` 那个最安全的站点会被判违规,规则只能被削弱。两侧计数 `(6,1)` 和 `(0,1)`,从合同背书降级为裸结算现在会双重失败。

### 判断为错误投入、明确不做的

**按文件拆 `cmd_job.zig`**（约 5,000 行生产码 + 2,200 行交错测试，60 个顶层函数）。
问题不在"都在一个文件里"，而在 `killJob`(680 行) 与 `removeJob`(545 行) 是同一个 12 步序列的两份，其中 4 行逐字节相同。
按文件切分会**保留**这份重复只是搬个位置，代价 43 个锚点。第 4 项才是这份重复真正的危险面——把漂移变成不可写比换个文件有用。

## 五、需要程序员决定的数据丢失语义（新增，均只报告未改行为）

1. **`server rm` 移走了守护私钥的那道 FK。** `servers.key_id REFERENCES keys(id)` 是 `NO ACTION`，
   所以有服务器引用某 key 时 `key rm` 会被**拒绝**。`server rm` 之后该 key 无人引用，而 `keys.remove` 是一句裸 `DELETE FROM keys`
   ——无事务、无屏障、无确认，材料不可再生。两条路径的消息都不提 keys。
   （更正我先前的说法：`server rm` **不**销毁私钥本身，风险是反向的。）
2. **`redaction_rules` 被 `server rm` 销毁，无屏障、无计数、无消息**，而它是**安全声明**（显式声明的 secret 位置，
   使脱敏不依赖模式猜测）。7 张级联表里唯一三重零保护的一张。
3. **已释放的 lease 历史随服务器消失且不被提及** —— 屏障数的是 claim，不是行。
4. **`host_pins` 不在级联里**（无 `server_id` 列，键是 `(host, port, key_type)`）。同 host:port 重建服务器会**继承** pin，
   所以风险是**过期 pin**而非盲信。当前零生产调用方，在 host-key 验证接上之前是惰性的。

## 十、目标 5：remote helper 的决策、论证与第一个可运行检查点

### 10.1 这台机器上有 Linux，所以「无法验证」的前提是错的

先前把目标 5 记为「等 B 类决策」，隐含的理由是它无法诚实验证：唯一的真实远端需要那把只存在于**禁止触碰的** `terminus.db` 里的 SSH key。

**这台机器有 WSL2 Ubuntu-24.04（Running）和 Docker（linux/amd64）。** 实测：Windows 上
`zig build-exe -target x86_64-linux-musl -OReleaseSmall` 产出的静态 ELF64（`ldd` 报
`not a dynamic executable`）**能直接在 WSL 里执行**。所以真 fork/setsid、真进程组、真
SIGTERM→SIGKILL、真 `/proc/<pid>/stat` 字段 22 全部可本地驱动。

**仍然覆盖不到，不得声称**：libssh2 自己的 channel、scp 推送 helper、`noexec /tmp` 回退、异构 arch 探测。那些依旧是真实远端专属。

### 10.2 B3 定为「分层，helper 为主路径」，而论据是纯 shell 结构性做不到

我顺着查过纯 shell 能否补强到 `pid_proof = .strong`，结论是**不能**，四条各自独立：

1. POSIX（XCU 2.5.2）规定子 shell 里 `$$` 仍展开为**父** shell 的 pid，所以 `( … )` 里的命令无法自报身份。
   这正是 `wrapShell` 注释早就写下的那句——**我的分析确认了它，不是推翻它**。
2. 改成 `( … ) & __t_pid=$!` 能拿到真 pid，但引入**竞态**：`ps`/`/proc` 读之前快命令就被 reap 了，token 为空。
   而快命令是常态，不是边角。
3. 后台化会让子进程在非交互 shell 下拿到 `/dev/null` 作 stdin，**直接砸掉已交付的 `--stdin-file`**（目标 4）。
4. 唯一的纯 shell 出路是再套一层 `sh -c '…$$…'`，但那会改变 `--shell none` 合同承诺的「每个 argv 元素恰好一个 shell 词」。

所以 `shell_capability.pid_proof = .weak` **是对的，留着**。helper 之所以能做到，是一个**排序**事实而不是更聪明的代码：
**父进程自己掌握 reap，所以子进程哪怕瞬间退出也还是 zombie，`/proc` 条目照样可读——竞态不是赢下来的，是被消掉的。**

### 10.3 已验证的检查点

`src/helper/main.zig`（约 470 行，无 allocator，全定长缓冲）。协议是双向长度前缀帧
`[u32 LE len][u8 kind][payload]`。终态帧的 `how` 字段把目标 6 要的区分**写进线上**：
`timed_out_killed`（deadline 触发**且**已确认进程组消失）与 `timed_out_unconfirmed` 是两个值，
后者才是 `indeterminate`——把两者并成一个，就是把「我们叫它停了」谎报成「它停了」。

`x86_64-linux-musl` / ReleaseSmall = **11,560 字节**，所以嵌进 CLI 基本不要钱
（先前按 ReleaseSafe 估的 3.4 MB 是带 `std.fmt` + writer 的版本，纯 syscall 版差三个数量级）。

在真 Linux 内核上跑过 **20 条断言全绿**，其中七条是 shell 模式做不到的：

| 证明的事 | 为何 shell 做不到 |
|---|---|
| **12/12 快命令都报回非零 start token** | `/bin/true` 在读之前就没了；见 10.2 第 2 条 |
| `pgid == pid`（子进程 setsid 成功），且 pgid 是**读回来**的不是假定的 | shell 拿不到子 shell 的 pid |
| NUL 字节与伪造的 `__TERMINUS_EXIT_1__ code=9` 逐字节穿过，**且没变成状态** | shell 模式在流里嵌标记，回显真 nonce 的命令能伪造终态 |
| 被信号杀 ≠ 退出码（`waitid` 的 `CLD_KILLED` + signal 9） | `$?` 把它压成 137 |
| deadline 是 helper 自己的：TERM 先试（状态 15），被 `trap ''` 挡住才升级 KILL（状态 9） | 无 `timeout(1)` 就没有；SSH 断开后子 shell watchdog 行为不确定 |
| 三个脱离父 shell 的孙进程（`sleep 41 & ×3`）**全部消失** | `kill -pid` 留下它们 |
| `execve` 失败算**命令的** 127，不算 helper 失败 | — |

两条超时臂互相钉住：第 7 条断言状态必须是 **15**，第 9 条必须是 **9**。
只断言 `timed_out_killed` 的话，第 9 条在 TERM 生效时也会过——**它就没有证明升级真的发生**。
第一版正是这么写的，被 `sleep 30` 打出来了（我原本硬编码期望 9，而 helper 报的 15 才是对的）。

### 10.4 一处必须更正的判断，而它让下一步变便宜

我写过「缝是这次验证的前置」。**错。** `Executor` 本来就是一道缝
（`union(enum) { direct, daemon, scripted }`），加第四个变体跑真 shell 是纯增量，`runCommand` 一行不用改。
是两道**不同**的缝，只有第二道是重构：

- 换 supervisor（PowerShell、helper） → `runCommand` 里的 Supervisor 缝（重构）

顺带更正另一句我说过的话：「今天所有 supervisor 门禁跑的都是 `Scripted`」**也是错的**。

### 10.5 mutation 跑出来的四件事（这一节是本轮最有价值的部分）

九条 `G5-` 锚点最终 **9/9 全杀**，每条落在一个有名字的检查上。但**第一轮有 3 条存活**，
而那 3 条各指出一个真问题——修的是代码和门禁，不是把断言改松：

1. **`readPgid` 和子进程 `setsid()` 是竞态的，而后果是 helper 杀自己。**
   父进程读早了就拿到 **helper 自己的 pgid**，于是后面每一次 `kill(-pgid, …)` 打的是自己这一组。
   没有 `start_new_session` 时 helper 和驱动器同组 → **TERM 打死驱动器**（我看到的 8 次 rc=15 就是它）；
   隔离之后 → **打死自己**，于是没有终态帧。
   「读回来而不是假定」这个直觉是对的，但**读回来的那一下正是竞态所在**。
   修法是一条 `CLOEXEC` 同步管道：子进程 `setsid` 后写一个字节再 `exec`，父进程收到才允许问 pgid；
   收不到就 pgid=0，`stopGroup` 退回按 pid 发信号。顺序从此是硬的，不是赌调度。
2. **`/proc` 的 `starttime` 精度是 10ms 一个 tick，而 fork 只要微秒。** 所以 helper 和它的子进程
   **落在同一个 tick 里、两个 token 相等**——我那条「token 是子进程的而不是 helper 自己的」门禁
   **根本区分不出父子**，报自己 starttime 的 mutation 直接活了过去。
   修法不是改断言，是**把请求晚 400ms 送进 helper 的 stdin**（`( sleep 0.4; cat req ) | helper`）：
   helper 早已在跑，子进程晚 40 个 tick 才出生，比较这才有分辨力。
3. **`frameOut` 的分块循环是不可达代码。** 唯一的大 body 来自 `pump`（32 KiB 缓冲），而 `out_buf` 是 64 KiB，
   所以 `chunk` 永远等于 `body.len`，第二次迭代进不去。删掉循环，改成单帧 + 一条
   `comptime { assert(pump_bytes <= out_buf.len - 5) }`——**界从「被应付」变成「被声明」**。
   锚点改成把长度少算一个字节（漏掉 kind 字节），打在活的那行上。
4. **`linger_ms` 不承重。** 把它设成 0 的 mutation 通过了全部门禁，因为**子进程在管道收下它的输出之前根本退不了**，
   剩下的字节由循环后那段有界排空取走。整个窗口删掉：它唯一的效果是去等我们本来就不该等的孙进程。

另外两件工程性的：**夹具的隔离必须被安排，不能被假定。** 被测对象能杀掉测它的东西（上面第 1 条），
解析器越界 panic 会把诊断指到错的地方（帧长那条最初报的是 `struct.error`，不是一条具名失败）——
两边现在都校验帧长并给出名字。还有 `pgrep -fc 'sleep 41'` 是错的检查：它按文本匹配，
把前几轮泄漏的进程一起数了（`before=19`）；正确的检查就是那个断言本身——`kill -0 -<pgid>`，
孙进程继承 pgid，所以组里只要还有一个它就成功。

顺带第三次踩到同一个形状：`pkill -f 'sleep 4'` 把它自己的父 shell 杀了，
因为那个 `sh -c "…"` 的命令行里就含着 `sleep 4`。**扫描器的针写在它自己扫描的文本里**，
台账第七节已经记过两次。用 `pkill -x sleep` 按进程名匹配。

### 10.6 `wsl.exe` 无法被 `std.process.spawn` 启动（花了十次实验，值得留档）

九条 helper 门禁写完后**全部红**,而症状是「没有终态帧」。真因和 helper 无关:

**`wsl.exe` 在 Zig 的 `std.process.spawn` 创建的进程里根本起不来。** 它回一段 UTF-16:
「RPC 调用包含的某个句柄不同于声明的句柄类型。错误代码: `Wsl/Service/0x8007072c`」
——Win32 1836,`RPC_X_SS_HANDLES_MISMATCH`。

排掉的东西(每一条都实测过,不是推理):`create_no_window` 两个值、stdin 的 `ignore`/`inherit`、
stdout 的管道/继承/忽略、PATH 上两个 `wsl.exe` 加 `System32\bash.exe`、父 shell 是 bash / cmd / powershell、
`wsl.exe -d` 与 `--system`、以及**中间垫一层 Python 也不行**。

根因在 `Threaded.zig:16236`:`CreateProcessW` 带 `bInheritHandles = .TRUE` 且**不带
`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`**,所以进程里每个可继承句柄都过去了。交互 shell 和 Python 的
`subprocess`(默认 `close_fds=True`)都限制了这个集合,两者都能用——**限制本身就是那个差别**。

**解法是复用树里已有的那条路**:外层用 `posix_sh`(build 已经发现它,而且这里另外两个门禁已经在成功 spawn 它),
由 MSYS 的 fork/exec 去启动 `wsl.exe`。另外两处必须同时处理:

- 命令写进**文件**,不能放进 `-c`。放进去就落在外层 shell 的双引号里,而命令里有 `$$`、`$i`、`$((…))`,
  外层会在内层看到之前全部展开——那时门禁测的就不是它写的命令了。
- 给 `wsl.exe` 的是**裸文件名**,前面先 `cd`。MSYS 会把传给 Windows 程序的、看起来像路径的参数改写,
  `/mnt/c/...` 到 `wsl.exe` 手里会变成 `C:\...\mnt\c\...`。脚本**内容**里的 Linux 路径从不出现在命令行上,所以没人碰它。
  (同一个坑今天从 bash 手动跑时也踩过一次,那边是用 `MSYS_NO_PATHCONV=1` 关掉的。)

顺带记一条:**MSYS 挂在 `/<drive>`,WSL 挂在 `/mnt/<drive>`**,所以是两个映射函数(`msysPath` 与 `linuxPath`),
不能合并。

## 十一、发布阻断项：daemon 传输现在拒绝每一条命令

host-key 信任链上线后,`daemon/Server.connectFor` 传的是 `TrustRoot.none`,而 `Ssh.connect` 对 `.none`
在拨号前就拒绝。**daemon 是默认传输**,所以每一条普通命令现在都失败,除非操作者加 `--no-daemon`
或 `TERMINUS_NO_DAEMON=1`。这不可发布。

`.none` 本身是**对的**:daemon 的协议在每个请求里携带认证材料,正是为了让它永不碰 sqlite,
所以它没有任何 `host_pins` 行可读。两个被否掉的替代方案各有决定性理由:

- **daemon 打开默认库。** 否。跑 `--db <other>` 的 CLI 会被一个操作者从未在其中记录过 pin 的信任根授权;
  而且后台 daemon 会去开 `%APPDATA%\terminus\terminus.db`——硬约束禁止的那个库。
- **CLI 不再提供 daemon。** 实测过并回退了:**会砸掉 35 个 blackbox 门禁**。
  `test/blackbox.zig` 的 `FakeHost` 靠绑定 scratch HOME 里的 daemon socket,
  而那是这棵树里唯一能把一个脚本化的主机放到真二进制面前的办法——直连需要监听的服务器和真实密钥,
  `zig build test` 两样都没有。**更整洁的那条路是门禁更少的那条路。**

**正在做的修法**:请求携带它自己的授权。`protocol.Request` 加一个 `trust` 字段(key_type + fingerprint),
版本 3 → 4;`connectFor` 用它构造 `pins` 根;**CLI 从自己的库里读出 pin 再发过去**——
权威留在持有库的那个进程里,daemon 只负责比较,不负责决定。

一处必须同时处理的正确性要求:**池化的连接带着它当初被授权的身份。** `Pooled.keyOf` 现在是
`host\0port\0username\0auth-tag`(`{t}` 只取 union 标签,不含材料),所以指纹必须进 key——
否则一个带 pin Y 的请求会复用在 pin X 下建立的连接,等于授权了没人 pin 过的东西。
