## 五、支线闭合后的自主路线

按依赖排，不碰被锁的四项：

- **M3**：ByteStream + ArtifactTransfer（目标 3、4）。采用 ringio 的 `pipe`（Disruptor 环包装成 `std.Io.Reader`/`Writer`，零拷贝背压）和 `slotmarks` 的连续前缀语义（durable offset 只推进到**第一个缺口**，不是最高完成块；权威值落 SQLite）。**不**引入 `RingIo` 作为 `std.Io`——已实测为可证明的空操作，见 memory。
- **目标 2 补齐**：`job kill`/`job rm` 各自的 control operation（`job_control` kind 已定，无需 migration）
- **M4**：cursor 分离、marker 跨窗口、progress/businessResult 落库、memory freshness、handoff（目标 7、8、11、12）
- **目标 13**：`--argv-json` + 显式 shell → 解锁 **目标 15**
- **目标 9 补齐**：`job receipt`
- **M6 本地门禁**：单元/状态机/JSON golden、migration 多版本与并发、redaction 负向、>2GiB 峰值内存、任意 offset resume、no-clobber 竞争、ENOSPC、rename 失败

到这里本地门禁应当全绿，然后**停在四份合同和发布前面**。

## 六、纪律（已被这条支线反复验证过的）

- 改过 anchored 文件后跑 `python tools/mutate.py --check-anchors`；绿测试看不见死锚点
- 锚点唯一性必须程序化计数，不许肉眼
- 一个 mutation 若被编译器抓住，它什么都没证明——重新推导直到是门禁在失败
- 文档里的值/退出码若无门禁解析，就是无保护的；已因此漏过三次
- 匿名 `test {}` 也是一个 test：聚合器用 `comptime { _ = @import(…) }`，不用 `test {}`
- 每轮 mutation run 后 `.zig-cache` 涨约 7.5 GB；整个删掉，冷编译约 90 秒
- 只说"零 `CONNECTION_RESET`"，不说"零输出痕迹"——有四个测试故意打印诊断
